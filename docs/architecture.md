# 代码结构与维护边界

生产代码及私有头文件位于 `src/`，测试和测试支持代码位于 `tests/`，生成文件只进入构建目录。内部静态目标用于隔离依赖，不发布公共库。不设置文件行数上限；开发约束见根目录 [AGENTS.md](../AGENTS.md)。

| 模块 | 职责与依赖 |
| --- | --- |
| `core` / `pa_engine` | 冻结的 Windows 指针引擎，仅依赖 C++ 标准库 |
| `platform` | 路径、原子 JSON I/O、ELF 运行标识；构建元数据独立到 `pa_runtime_info` |
| `config` | 配置类型与序列化、配置仓储、revision 和持锁写入事务 |
| `input` | libinput 报告采集和 ELF 导入表事务；纯坐标/批次校验单独编译 |
| `maintenance` | 原生清单校验、启动事实收集与纯状态判断、会话监测、修复 |
| `control` | D-Bus 传输、状态组合及配置保存/生效协调 |
| `gui` | 无 I/O 的草稿状态、后台工作对象、控制器和 QWidget 视图 |
| `kwin` | 插件装配、D-Bus 外观、输入会话、批次映射、逐报告重放和诊断 |
| `probes` | Wayland/X11 原始输入诊断客户端，保留直接协议实现 |

依赖从 GUI/CLI 指向控制、配置和维护模块；KWin 模块只链接输入所需的配置、平台、采集和 KWin 适配。CLI 不依赖 Qt Gui/Widgets，GUI 不依赖 KWin 私有库。`PA_BUILD_DESKTOP=OFF` 在查找 Qt、KWin、Python、libinput 之前结束桌面配置，因此引擎测试可独立构建。

## 配置提交与 GUI

`ConfigRepository` 负责配置快照、文件原字节的 SHA-256 revision 和原子写入。`Transaction` 在读取配置前持有 `config.lock`，校验 revision 和新配置，再写入；控制客户端在事务仍存活时请求 `ApplyConfig`，保持原有锁覆盖范围。

保存成功和应用成功分别报告。模块离线或应用失败时，已经保存的配置仍有效；损坏文件或冲突不会被默认值覆盖。原有 `configuration/readConfig/writeConfig` 函数是统一仓储的兼容入口。

D-Bus 传输只负责请求和回复解析。状态组合显式接收配置快照、启动结果、运行回复及自启事实，不执行 I/O。GUI 一次检查把同一份 `ConfigSnapshot` 交给状态查询，避免再次读取不同版本的配置。诊断导出保留完整协议对象及未知字段。

`ConfigDraft` 独立维护草稿、已保存值、外部最新值及 revision，不依赖 QObject、文件或 D-Bus。控制器负责异步调度、文件监测和视图通知；工作对象及每个实例独有的 D-Bus 连接只在工作线程使用。刷新保留未保存草稿，控件回填阻断信号，关闭窗口不改变模块寿命。

## 输入会话与重放

`InputSession` 负责设备热插拔连接、原信号接管/恢复、capture 启停及零输出 raw 过滤器。`PointerRuntime` 保留唯一引擎、配置、临时启停覆盖和诊断；多只鼠标共享同一个引擎。

`InputBatch` 先取出报告，再验证整批原始/加速位移总和、来源和时间戳，并完整映射设备。只有整批通过后才进入 `motion_replay.cpp`：按原序逐份选择当前光标所在屏幕、处理位移并发送 frame。排除设备、不适用设备和非整数 raw 透传且不推进引擎。任何批次异常先停用接入，再将原合并事件透传一次。

配置切换先停用接入、读取配置、验证运行兼容性，再配置引擎并恢复接管。只有原有启停规则或显式 reset 清除引擎状态；速度/EPP 切换不隐式清空余量。输入路径不访问磁盘或同步 D-Bus。采集队列与 ELF 导入表事务内部实现未在此次结构重构中改写。

KWin 会跳过加速位移为零的相对消息。模块在正常 Forward 过滤器前补发其非零 raw，锁屏、拖拽和其他先行过滤器继续先处理事件。每份报告的 frame 保留 XWayland raw motion，不能改为整批只发送一次。

## 兼容与安装维护

启动检查分为 `collectStartupFacts` 和纯 `evaluateStartup`。内部使用 `StartupState`，序列化保持原有状态字符串及字段；事实收集按本地校验、软件包、二进制、会话的顺序读取，前置校验失败时不执行昂贵的后续检查。会话监测继续按已检查的 D-Bus owner 加载，每个 owner 不自动重试；磁盘升级不卸载仍在正常运行的旧模块。

Python 维护脚本和 C++ 原生校验器遵守同一个 TSV 清单契约。Shell 委托维护脚本校验；两种实现通过同一测试数据集验证。必要记录、文件 digest、链接目标、路径范围和重复文件必须有效；允许旧安装的最小清单与升级中累积的重复目录记录，以保留迁移兼容。

用户文件和系统模块仍采用原有事务、备份、提交、回滚及恢复协议。系统权限操作保持在独立 Shell 入口。源码快照包含构建文件、presets、开发规范、格式配置、完整生产源码和测试，排除链接、缓存与构建输出；解包先校验全部成员，拒绝路径越界及特殊文件。

模块绑定 KWin 的版本 IID；安装检查核对库和可执行文件的 SHA-256，插件工厂在创建运行对象前核对进程内 GNU Build ID。支持 KWin 6.7/6.8，6.9 及以后拒绝构建。`PA_TESTING` 仅用于隔离测试目标，正式模块不编入测试 D-Bus 方法、虚拟设备及报告注入实现。

算法来源及历史基线见 [algorithm-origin.md](algorithm-origin.md)，测试分层和命令见 [testing.md](testing.md)。引擎冻结检查使用当前源码校验值，与上游导入时的历史哈希分别维护。
