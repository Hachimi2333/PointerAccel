# 代码结构与维护边界

所有手写生产代码及私有头文件位于 `src/`，同一职责的声明和实现就近放置。测试位于 `tests/`，生成的构建信息与协议代码位于构建目录。内部静态目标用于共享编译和隔离依赖，不作为对外库发布；不设置文件行数上限。

| 子目录 | 职责 |
| --- | --- |
| `core` | 指针引擎、速度与 DPI 计算；不依赖 Qt、KWin 或 I/O |
| `config` | 配置类型、校验、序列化、统一快照读取与原子保存 |
| `platform` | 应用路径、JSON 文件 I/O、构建信息和 ELF 运行标识 |
| `input` | libinput 报告采集、导入表事务、原始坐标与批次校验 |
| `kwin` | 插件装配、D-Bus 外观、设备接管、输入运行对象和诊断 |
| `control` | CLI/GUI 共用的 D-Bus 客户端和配置提交，区分保存与生效 |
| `maintenance` | 安装验证、启动判定、会话监测和修复；共享文件监测事实 |
| `cli` | 命令解析、输出和安装脚本使用的 KWin 配置维护命令 |
| `gui` | QWidget 窗口、三页视图、设备模型、草稿控制器与后台工作对象 |
| `probes` | Wayland/X11 原始输入诊断客户端，保留直接协议实现 |

GUI 的视图只展示状态并发出编辑操作。控制器持有类型明确的配置草稿、已保存值与外部最新值；工作对象及私有 D-Bus 连接只在工作线程使用。JSON 保留在通信和诊断导出边界。控件回填阻断信号，不会产生配置提交或算法重置。

KWin 输入运行对象持有唯一引擎，多只鼠标共享其状态。先校验整批报告并匹配设备，再按原序逐份处理；每份报告处理前根据当前光标选择屏幕缩放，处理后发送 frame。设备不适用或被排除时透传，不推进引擎。队列、校验或接管异常时恢复原生路径，失败的合并事件只转发一次。输入路径不访问磁盘或同步 D-Bus。

配置仍使用原 JSON 字段，D-Bus 路径、接口、方法及 CLI 参数保持兼容。改变速度或 EPP 不隐式清空余量；只有原有启停规则或显式重置触发引擎 reset。涉及这些行为的后续修改必须通过独立参考模型、冻结基线和嵌套 KWin/raw 客户端测试，不能通过重生成期望值消除差异。

`PA_TESTING` 仅用于隔离测试目标：虚拟设备和注入实现位于测试目录，正式模块不编入这些接口。安装脚本的事务、备份与回滚流程保持原有实现；源码快照白名单跟随目录布局更新。

## 输入处理与兼容边界

引擎取自 `windows-pointer-linux`，源码融入 `src/core/pointer_engine.cpp` 和同目录的私有头文件，以 `pa::PointerEngine` 参与程序内部构建，不再提供独立引擎库或公共头文件目录。重构保留原有计算：Q16 定点数、1–20 档速度、EPP 分段和段间状态、带符号余量、零报告规则、多鼠标共享状态。有效显示 DPI 使用原引擎的 `round(96 × scale)`，限定于 96–480。无需再次输入鼠标 DPI 或回报率。来源提交和校验值见 [算法来源](algorithm-origin.md)。

KWin 6.7／6.8 适配沿用逐报告采集与重放路径，以处理 KWin 合并后的 libinput 位移。模块通过 ELF 导入表接管 libkwin 内的三个调用入口，保留每份报告，再按原顺序交回正常指针处理。它只临时写入导入表的数据页并恢复页权限，不改写机器指令、不创建可写可执行页。停用时恢复导入槽及原 Qt 信号连接。每份重放报告都发送相应输入帧边界，以保留 XWayland raw motion。

Windows 整数输出可能为零，即使原始报告非零。KWin 默认会跳过这种报告的相对消息，因此模块在正常转发过滤器之前补发其 raw 数据；锁屏、拖拽和其他先行过滤器仍先处理事件。桌面位移继续保持算法输出的零值。

模块加载、输入拦截和 KWin 版本检查是不同层次。二进制模块遵守 KWin 的版本 IID，检查服务核对构建时的 KWin 库和可执行文件 SHA-256，模块工厂在创建输入处理对象前核对进程内的 GNU Build ID。缺少导入入口、原函数不匹配、报告校验失败、队列溢出或崩溃恢复启动时，算法不会继续应用。报告批次验证在推进引擎状态前完成，失败批次按原合并事件传递一次。

此适配依赖 KWin 内部接口。支持 KWin 6.7／6.8 系列，6.9 及以后明确拒绝构建，需审查适配。本次使用 6.8.2 的开发头文件和嵌套 KWin 验证原有输入接入路径，未新增版本分支；6.7 沿用此前 6.7.5 的验证记录。已安装本适配后，同系列软件包升级可运行 `pointeraccel repair` 进行构建和测试，修复后重新登录以加载对应的新模块。首次从旧版增加 6.8 支持需使用更新后的项目源码运行 `./install.sh`。算法一致性不等于对所有 Windows 版本、游戏或硬件延迟的独立认证。
