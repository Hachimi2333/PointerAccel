## 算法来源与可确认范围

测试时的上游提交：`0bdd644d420737a7aea506e252fc5e12db34c599`。当时上游工作副本的 `git status --porcelain` 为空，engine.cpp 与 engine.hpp 相对上游提交没有修改。之后移除原项目文件夹时，将这两个文件按原字节保留到本项目的 `src/windows_pointer/engine.cpp`、`include/windows_pointer/engine.hpp`；以下校验值不变，详见 [算法来源](algorithm-origin.md)。

- engine.cpp SHA-256：`698a09996ae6086e5414da23c84ca2f8c0156ffd99a6a5ba6ec8484c99c6950e`
- engine.hpp SHA-256：`bfb4a1969ca0dd22af632c9796040cc4ce136ae04d8eff8a9f0f138aac809ff7`

本项目通过 CMake 直接构建保留的原始引擎源码，生成 windows_pointer_engine 并链接进 KWin 模块，没有第二套曲线实现。默认曲线常数、Q16 运算、速度映射、EPP 段历史、有符号余量、零报告规则以及缩放映射均由同一引擎负责。KWin 接入层逐报告调用 Engine::apply，不再叠加 KDE 指针速度倍率。

可以确认：相同原始报告序列、设置、显示 DPI 与初始状态下，核心算法规则没有改动；以上已安装二进制与真实轨迹对比未发现数值差异。

此结论不表示 KWin 与 Hyprland 的渲染、边缘限制、调度及呈现时序完全相同，也不等于独立核验了所有 Windows 版本。本次没有测量真实端到端延迟，没有在实际游戏内验证，没有测试真实混合缩放多屏。
